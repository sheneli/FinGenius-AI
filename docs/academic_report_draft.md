## 1. Introduction and Problem Domain

Money management is one of the strongest levers on daily lifestyle: spending habits shape routines, savings shape long-term options, and financial uncertainty is a recognised source of stress that spills into productivity and wellbeing. Yet mainstream personal-finance apps largely remain transaction ledgers: they record what happened but do little to explain it or to change behaviour. This project develops **FinGenius AI**, an Android financial-wellness companion, as the financial-domain instantiation of the module's *AI-Driven Smart Lifestyle Companion* brief. Rather than sensing the physical environment, the application senses the user's *financial* environment — spending patterns, pay cycles, recurring obligations — and adapts its guidance accordingly.

The aim was to design and build a production-standard application that goes beyond CRUD: on-device receipt OCR and voice capture reduce entry friction; a layered AI pipeline categorises spending and learns from corrections; explainable analytics (a transparent financial-health score, exponential-smoothing forecasts with uncertainty bands) inform the user honestly; and a Gemini-powered assistant answers questions grounded in the user's aggregated data under strict safety validation.

## 2. Literature Review

Dey's (2001) definition of context — any information characterising an entity's situation — underpins the design: here, context is temporal (payday proximity, quiet hours) and behavioural (spending patterns, recurring merchants) rather than locational, a deliberate privacy-preserving substitution. Kaye et al. (2014) found that people track finances through idiosyncratic, emotionally-charged practices and often distrust opaque tools; this motivated FinGenius AI's insistence on explainability — every score factor and forecast band is inspectable. Fernandes, Lynch and Netemeyer's (2014) meta-analysis shows that financial education alone has weak downstream effects, supporting "just-in-time" behavioural nudges over static advice; Thaler and Sunstein's (2008) nudge theory and Fogg's (2009) behaviour model shaped the notification strategy (timely prompts at moments of ability and motivation, never shaming). Davis's (1989) TAM informed the emphasis on perceived usefulness (sub-15-second capture) and ease of use.

**Comparison with existing systems.** Mint (Intuit) demonstrated aggregation-centric PFM but was discontinued in 2024, highlighting the fragility of bank-scraping models; YNAB offers rigorous envelope budgeting but demands high manual discipline and a subscription; Emma and Cleo add conversational AI, but their guidance and scoring logic are opaque to users. The gap FinGenius AI targets is a *transparent, privacy-first* companion: on-device OCR before any cloud call, aggregate-only AI prompts, a documented health-score formula, and honest uncertainty — positioning intelligence as inspectable rather than oracular.

## 3. Methodology

Development followed an iterative, vertical-slice lifecycle: each feature (authentication, transactions, budgets, OCR, AI assistant…) was taken from domain model through repository, state management, UI states and tests before the next began, keeping the app releasable at every step. Requirements were captured in a product-requirements document with personas and journeys, then traced to rubric criteria in a Requirements Traceability Matrix. Technology selection (Flutter/Dart, Firebase Auth/Firestore/Storage/Messaging/Remote Config/Crashlytics/App Check, ML Kit Text Recognition v2, Gemini via Firebase AI Logic, Riverpod, GoRouter, Hive) was justified per dependency, prioritising official SDKs, null safety and maintenance status. AI ethics were treated as requirements: consent gating, data minimisation, output validation and rate limiting were designed before the assistant feature itself.

## 4. System Architecture

The application uses Clean Architecture with feature-first organisation and MVVM (Figures 1–2): pure-Dart domain layers (entities, financial algorithms) depend on nothing, data layers implement repository interfaces against Firebase and a Hive cache, and Riverpod notifiers act as ViewModels. A generic `OwnedCollectionRepository` provides the offline-first contract — optimistic local writes queued as idempotent operations, flushed with exponential backoff; conflicts resolve last-write-wins on server timestamps with deletes winning (Figure 4). All cloud data lives under `users/{uid}` enforced by default-deny security rules (Figure 3). This modularity is what makes the system scalable and maintainable: features cannot reach into each other's data layers, and each dashboard section derives from its own provider.

## 5. Design and Implementation

The UI implements Material Design 3 through a semantic token system (colour, spacing, radii, motion, chart palette) with a dark-first brand identity (deep navy, green→cyan growth gradient, gold accents; the original "Orbit G" logomark was developed from three documented concepts). Navigation uses a five-tab shell (Home, Activity, Assistant, Plans, Profile) with GoRouter guards for authentication, e-mail verification and biometric lock. Nielsen's (1994) heuristics guided visible system status (pending-sync badges, offline banner), error recovery (every screen has loading/empty/error states) and user control (every AI suggestion is correctable). Accessibility follows WCAG 2.1 (W3C, 2018): 48 dp targets, screen-reader semantics on gauges and charts, chart data tables as textual alternatives, and layouts tested to 200% text scale.

Intelligence is layered. Categorisation applies user rules, then learned corrections, then deterministic keywords, calling Gemini only for low-confidence cases — with every response validated against the known category set before use. The financial-health score is a documented weighted composite (savings rate 30%, budget adherence 25%, cash-flow stability 20%, emergency fund 15%, bill punctuality 10%), surfaced factor-by-factor and explicitly labelled "not a credit score". Cash-flow forecasting uses Holt's (2004) linear exponential smoothing with an empirical 80% uncertainty band derived from one-step residuals (Hyndman and Athanasopoulos, 2021), refusing to forecast on under three months of data and showing a backtest of past predictions against actuals. Receipt capture runs ML Kit Text Recognition v2 entirely on-device; a pure-Dart parser extracts merchant, date, total, tax and line items with per-field confidence, and the user corrects every field before a compressed image is uploaded. Duplicate and subscription detection use amount/interval/merchant-similarity heuristics with user confirmation.

## 6. Security and Privacy

Security follows OWASP MASVS themes: Firebase Authentication with verification and re-authentication before deletion; ownership-based Firestore/Storage rules (emulator-tested, default-deny) with server-side type/range validation; App Check with Play Integrity; biometric app lock; encrypted local preferences; FLAG_SECURE on balance screens; least-privilege permissions (no location). Privacy is architectural: AI prompts contain only aggregated totals — never merchants, notes or raw transactions — and analytics (opt-in, default off) carry no financial values. Users can export everything (JSON/CSV) and delete their account end-to-end. A STRIDE threat model documents residual risks honestly.

## 10. Conclusion and Future Enhancements

FinGenius AI demonstrates that a mobile application can be simultaneously intelligent and honest: context-aware without surveillance, AI-assisted without opacity, and offline-capable without sync corruption. Future work includes tombstoned deletion sync, an on-device categorisation model — only once a genuine opt-in dataset and evaluation pipeline exist — richer payday-anchored periods, and, further out, edge inference and ambient/wearable surfaces for glanceable financial wellness.
